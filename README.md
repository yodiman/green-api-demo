# MAX чат через GREEN-API

## Как запустить

Node.js 20.19 или новее. Проект проверен на Node.js 24.19.

```bash
npm ci
npm run dev
```

Для подключения нужны три значения из личного кабинета GREEN-API: `apiUrl`, `idInstance` и `apiTokenInstance`. Их можно ввести прямо в форме. Если удобнее не вставлять их каждый раз, скопируйте `.env.example` в `.env.local` и заполните:

```env
VITE_GREEN_API_URL=https://your-api-host.example.com
VITE_GREEN_API_ID_INSTANCE=your-instance-id
VITE_GREEN_API_TOKEN_INSTANCE=your-instance-token
VITE_GREEN_API_RECEIVE_TIMEOUT_SECONDS=5
VITE_GREEN_API_POLLING_DELAY_MS=1000
VITE_GREEN_API_POLLING_ERROR_DELAY_MS=2000
```

После изменения `.env.local` dev-сервер нужно перезапустить.

`VITE_GREEN_API_RECEIVE_TIMEOUT_SECONDS` задаёт серверное ожидание long polling в допустимом диапазоне от 5 до 60 секунд. `VITE_GREEN_API_POLLING_DELAY_MS` задаёт паузу между успешными циклами, а `VITE_GREEN_API_POLLING_ERROR_DELAY_MS` - паузу после ошибки. При отсутствии или неверном значении используются указанные выше defaults.

## Безопасность

В рамках тестового задания браузер обращается к GREEN-API напрямую, поэтому `apiTokenInstance` передаётся в запросах и доступен в инструментах разработчика. Такой подход недопустим для production: токен должен храниться и использоваться только на backend, а клиентское приложение должно обращаться к собственному API без получения секрета. Переменные с префиксом `VITE_` также попадают в клиентскую сборку и не являются защищённым хранилищем.

## Что настроить в GREEN-API

Чтобы приложение могло получать входящие сообщения, у инстанса должны быть:

- пустой `webhookUrl`;
- включённый `incomingWebhook`.

Очередь уведомлений обрабатывается последовательно, поэтому лучше не открывать один и тот же инстанс сразу в нескольких вкладках - уведомления могут разойтись между ними. История чатов хранится только в памяти открытой вкладки и пропадёт после перезагрузки.

## Доступность

Интерфейс сделан с учётом базовых принципов a11y: используются семантические HTML-элементы, управление с клавиатуры, доступные названия элементов, модальный `dialog`, связанные с полями ошибки и live-region для новых сообщений. Анимация автопрокрутки учитывает настройку `prefers-reduced-motion`, а основные кнопки имеют увеличенную область нажатия.

## Ограничения

Это минимальная реализация под тестовое задание: поддерживаются только текстовые сообщения и личные чаты.

Номер телефона проверяется в формате, который принимает метод `CheckAccount`: 11 цифр с кодом `7` или 12 цифр с кодом `375`. Сложной маски и отдельного выбора кода страны нет.

Черновики сообщений не сохраняются. При переключении чата поле ввода очищается.

## Где что находится

- `src/app` - запуск приложения, провайдеры и управление сессией;
- `src/features/session` - подключение к инстансу;
- `src/features/chat` - чаты, сообщения, очередь уведомлений и состояние интерфейса;
- `src/shared/api/green-api` - запросы к GREEN-API и проверка ответов.

Состояние чатов и сообщений живёт в TanStack Query. Zustand используется только для локальных вещей вроде выбранного чата и состояния формы.
